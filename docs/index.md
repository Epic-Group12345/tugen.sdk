# TUGEN SDK

> **TUGEN запускает любую игру — достаточно сделать для неё мини-приложение.** Мини-приложение на
> React Native берёт на себя всё, что нужно конкретной игре: установку, загрузки, настройки, запуск.
> Лаунчер даёт ему окно, файлы, сеть загрузок и процессы — через этот SDK и только через него.

## Как устроено

```
Лаунчер (tugen.launcher)
 ├─ своё окно, аккаунт, настройки
 ├─ острова поверх страницы: плашка сверху (иконка + название), навигация снизу
 └─ страница мини-приложения →
      <HostProvider value={host}>
        <SafeAreaProvider value={insets}>
          <App width height section safeArea />   ← мини-приложение (этот SDK)
        </SafeAreaProvider>
      </HostProvider>
      │
      ├─ GameHost: реализация лаунчера поверх нативных модулей и ядра tugen.core
      └─ insets: сколько места по краям закрывают острова лаунчера
```

- **Пространство игры** — своя папка. Все пути в `GameHost` — внутри неё, через «/»; путь за её
  пределы лаунчер отклоняет. Игра не видит файлов, базы и токенов лаунчера и других игр.
- **`defineGame`** — описание мини-приложения: `manifest` (id, название, версия, иконка, разделы) и
  корневой компонент `App`. Пакет игры отдаёт его экспортом по умолчанию.
- **`useHost()`** — доступ к лаунчеру из любого компонента мини-приложения.
- **`useSafeArea()`** — отступы, закрытые островами лаунчера (см. «Safe Area»).

## Иконка и название

Пока мини-приложение открыто, лаунчер показывает в верхней плашке его `manifest.name` и
`manifest.icon` — имя иконки [Gravity UI](https://gravity-ui.com/icons) в PascalCase, например
`'Cube'`. Без иконки в плашке — значок лаунчера по умолчанию. `defineGame` отклоняет имя не в
PascalCase.

```tsx
export default defineGame({
  manifest: { id: 'my-game', name: 'Моя игра', version: '1.0.0', icon: 'Cube' },
  App,
});
```

## Safe Area

Мини-приложение получает всю область страницы, но поверх неё лежат острова лаунчера: плашка сверху и
навигация снизу. Сколько они закрывают по каждому краю, в DIP, — `SafeAreaInsets`
(`{ top, right, bottom, left }`). Под островами можно рисовать фон, а нажимаемое и текст — только
внутри.

- `useSafeArea()` — отступы в любом компоненте. Вне лаунчера (превью, тесты) и в отдельном окне — нули
  (`ZERO_INSETS`), без ошибки.
- `safeArea` — то же значение пропом `App`, если так удобнее.
- `<SafeAreaView edges={['top', 'bottom']}>` — `View` с `padding` по отступам на перечисленных краях
  (по умолчанию на всех четырёх). На этих краях `padding` из `style` перекрывается, остальные не
  трогаются.

```tsx
import { SafeAreaView, useSafeArea } from '@tugen/sdk';

function App() {
  const { bottom } = useSafeArea();
  return (
    <ImageBackground source={art} style={{ flex: 1 }}>
      {/* фон уходит под острова, контент — нет */}
      <SafeAreaView style={{ flex: 1 }}>
        <Content />
      </SafeAreaView>
      <Toast style={{ bottom: bottom + 16 }} />
    </ImageBackground>
  );
}
```

Отступы меняются вместе с окном лаунчера — берите их из хука или пропа, а не запоминайте.

## Разделы

Игра объявляет свои разделы — сервисы издателя — в `manifest.sections`: id, название и иконку
Gravity UI. Боковой панели у лаунчера нет: разделы — это список для лаунчера, а саму навигацию по ним
(вкладки, меню) мини-приложение рисует в своём UI. Лаунчер помнит открытый раздел и передаёт его в
`App` пропом `section`.

```tsx
export default defineGame({
  manifest: {
    id: 'my-game',
    name: 'Моя игра',
    version: '1.0.0',
    sections: [
      { id: 'overview', title: { ru: 'Обзор', en: 'Overview' }, icon: 'House' },
      {
        id: 'servers',
        title: { ru: 'Серверы', en: 'Servers' },
        icon: 'Server',
      },
    ],
  },
  App: ({ section }) => (
    <SafeAreaView style={{ flex: 1 }}>
      <Tabs /> {/* свои вкладки: по нажатию — useHost().navigation.open(id) */}
      {section === 'servers' ? <Servers /> : <Overview />}
    </SafeAreaView>
  ),
});
```

Сменить раздел из игры — `host.navigation.open(id)`, закрыть мини-приложение и вернуться на главную
лаунчера — `host.navigation.exit()`. Первый раз открывается первый раздел, дальше — последний
открытый.

## Отдельное окно (запланировано)

`manifest.presentation` говорит, где открывать мини-приложение:

| Значение     | Где                                                            |
| ------------ | -------------------------------------------------------------- |
| `'embedded'` | в окне лаунчера на месте страницы, под островами. По умолчанию |
| `'window'`   | отдельное окно ОС — запланировано                              |

Лаунчер, который отдельных окон пока не умеет, открывает `'window'` как `'embedded'`. Поэтому
верстайте под оба варианта: держите контент в Safe Area — в отдельном окне отступы будут нулевыми, и
вёрстка останется верной.

## GameHost

| Часть        | Что даёт                                                                           |
| ------------ | ---------------------------------------------------------------------------------- |
| `navigation` | открыть раздел, закрыть мини-приложение                                            |
| `files`      | чтение и запись текста, удаление, копирование папок, распаковка zip, открыть папку |
| `downloads`  | пачка загрузки: параллельно, со сверкой SHA-1 и пропуском готового; отмена         |
| `process`    | запуск процесса игры, вывод строками, код выхода, завершение                       |
| `system`     | память компьютера, язык интерфейса                                                 |

Точные типы — [src/host.ts](../src/host.ts).

## Как мини-приложение попадает в лаунчер

- **В составе лаунчера** — пакетом, который лаунчер собирает в свой JS-бандл (так сейчас Minecraft):
  мини-приложение обновляется у игроков по воздуху вместе с лаунчером.
- **Пакетом `.map`** — отдельным файлом, без пересборки лаунчера. Пока — в режиме разработчика.

## Пакет .map

`.map` (mini application package) — как `.apk` у Android: обычный zip.

```
my-game.map
 ├─ manifest.json   ← MapManifest: { format: 1, sdk: '0.3.0', entry: 'bundle.js', game: { id, name, … } }
 └─ bundle.js       ← бандл мини-приложения, CommonJS
```

- `format` — версия формата пакета (`MAP_FORMAT`, сейчас 1). Пакет с незнакомым форматом лаунчер не
  открывает.
- `sdk` — версия SDK, под которую собран пакет (x.y.z).
- `entry` — путь бандла внутри zip: относительный, через «/», без `..`, оканчивается на `.js`.
- `game` — манифест игры; проверяется так же, как в `defineGame` (`validateManifest`).
- Бандл — CommonJS. Экспорт по умолчанию (`module.exports.default` или сам `module.exports`) —
  результат `defineGame(...)`.

Лаунчер разбирает `manifest.json` через `parseMapManifest(text)` — `{ ok: true, manifest }` или
`{ ok: false, error }`.

### Как собрать

В SDK есть CLI `tugen-map`:

```bash
yarn tugen-map build                       # src/index.tsx + src/manifest.ts → dist/<id>.map
yarn tugen-map build src/app.tsx --manifest src/meta.ts --out build/game.map
```

- `entry` (по умолчанию `src/index.tsx`) собирается esbuild-ом: CommonJS, `es2019` (Hermes),
  JSX automatic. Всё, кроме модулей песочницы, вшивается в бандл.
- `--manifest` (по умолчанию `src/manifest.ts`) — модуль с экспортом `manifest: GameManifest`. CLI
  выполняет его в Node, проверяет и кладёт в `manifest.json` — поэтому держите манифест отдельным
  файлом без React Native.
- `--out` — куда положить пакет, по умолчанию `dist/<id>.map`.

### Как поставить

Настройки лаунчера → режим разработчика → «Установить пакет .map», выбрать файл. Мини-приложение
появляется в лаунчере и открывается в песочнице.

## Песочница

Мини-приложение из пакета `.map` выполняется в песочнице: бандл получает через `require` только
модули из `SANDBOX_MODULES`, и SDK в них работает как обычно.

| Доступно                                                          | Недоступно                                            |
| ----------------------------------------------------------------- | ----------------------------------------------------- |
| `react`, `react/jsx-runtime`                                      | любые другие внешние модули — их надо вшить в бандл   |
| `react-native`: компоненты, стили, `Animated`, `Platform` и т. п. | `NativeModules`, `TurboModuleRegistry`                |
| `@tugen/sdk`: `useHost()`, Safe Area, `localize`, разделы         | `DeviceEventEmitter`, `NativeEventEmitter`, `Linking` |

Доступ к системе — файлы, загрузки, процессы — только через `useHost()`: так пути остаются внутри
пространства игры.

Честно о границах: это изоляция на уровне модулей JS в общем с лаунчером движке. Она закрывает
случайный и ленивый доступ мимо SDK, но **не является границей безопасности** от злонамеренного
кода — у бандла остаётся общий глобальный объект JS. Поэтому пакеты `.map` ставятся только в режиме
разработчика. Полная изоляция — свой JS-движок на мини-приложение — запланирована вместе с
`presentation: 'window'`.

## Версии

`defineGame` записывает в описание версию SDK (`SDK_VERSION`). Лаунчер не откроет мини-приложение,
собранное под более новую major-версию SDK, чем знает сам.

| Версия | Что добавила                                                                                                                                                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0.3.0  | `manifest.icon`, `manifest.presentation`; Safe Area: `useSafeArea`, `SafeAreaView`, проп `safeArea`; разделы рисует само мини-приложение; пакет `.map` (`parseMapManifest`, `SANDBOX_MODULES`, CLI `tugen-map`), `validateManifest` |
| 0.2.0  | разделы (`manifest.sections`), `navigation`, `localize`                                                                                                                                                                             |

Совместимость 0.3.0: новые поля манифеста необязательны, мини-приложение под 0.2.0 открывается как
есть. Но лаунчер нового дизайна не рисует боковую панель — игре с разделами под 0.2.0 нужен свой
переключатель разделов, а контент без Safe Area может уйти под острова. Старый лаунчер не знает
`icon`, `presentation` и не ставит `SafeAreaProvider` — тогда `useSafeArea()` даёт нули, а проп
`safeArea` не приходит.
