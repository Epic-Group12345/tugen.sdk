# TUGEN SDK

## Как устроено

```
Лаунчер (tugen.launcher)
 ├─ своё окно, навигация, аккаунт, настройки
 └─ страница игры → <HostProvider value={host}><App /></HostProvider>
                     │                          └─ мини-приложение игры (этот SDK)
                     └─ GameHost: реализация лаунчера поверх нативных модулей и ядра tugen.core
```

- **Пространство игры** — своя папка. Все пути в `GameHost` — внутри неё, через «/»; путь за её
  пределы лаунчер отклоняет. Игра не видит файлов, базы и токенов лаунчера и других игр.
- **`defineGame`** — описание мини-приложения: `manifest` (id, название, версия) и корневой
  компонент `App`. Пакет игры отдаёт его экспортом по умолчанию.
- **`useHost()`** — доступ к лаунчеру из любого компонента мини-приложения.

## GameHost

| Часть       | Что даёт                                                                       |
| ----------- | ------------------------------------------------------------------------------ |
| `files`     | чтение и запись текста, удаление, копирование папок, распаковка zip, открыть папку |
| `downloads` | пачка загрузки: параллельно, со сверкой SHA-1 и пропуском готового; отмена      |
| `process`   | запуск процесса игры, вывод строками, код выхода, завершение                   |
| `system`    | память компьютера, язык интерфейса                                             |

Точные типы — [src/host.ts](../src/host.ts).

## Как мини-приложение попадает в лаунчер

Сейчас — пакетом, который лаунчер собирает в свой JS-бандл: так мини-приложение обновляется у игроков
по воздуху вместе с лаунчером. Загрузка сторонних мини-приложений отдельными бандлами — позже.

## Версии

`defineGame` записывает в описание версию SDK (`SDK_VERSION`). Лаунчер не откроет мини-приложение,
собранное под более новую major-версию SDK, чем знает сам.
